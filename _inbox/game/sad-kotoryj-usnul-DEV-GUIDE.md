## 1. Что это

**«Сад, который уснул — история одной ошибки»** — браузерный ретро-платформер-квест
на vanilla canvas, один автономный HTML-файл (~1.7 МБ), без зависимостей и сборщиков.
Разрешение 480×270 (пиксель-арт, integer scale). Язык — русский.

Героиня **Мисс Тейк** получает в наследство заброшенный сад. 12 сюжетных уровней
в 4 актах + тестовый уровень 13. Игра полностью проходима. В файл встроены:
движок, редактор уровней, все спрайты (base64 PNG) и 17 повествовательных
кадров (base64 JPEG).

**Заказчик — Дмитрий, кинорежиссёр.** Критические правила работы с ним:
- Честная аргументированная критика, без комплиментарности. Ошибки и риски называть прямо.
- В кульминационных текстах НЕ использовать рубленые фрагменты («Холод. Тьма.») —
  только полные связные предложения. Рубленость допустима лишь как голос персонажа
  (КАПС Жёлудя/Энта, канцелярит Осы) или сухая ирония.
- Любые правленые тексты/промпты выдавать ЦЕЛИКОМ, не диффом.

**Сборка (обязательный ритуал после КАЖДОЙ правки шаблона):**
```python
# 1. инжект спрайтов и story-кадров
d = {имя: dataURI для всех pack/final/*.png + 9 легаси из assets/sprites}
html = template.replace('__SPRITES__', json.dumps(d))

# 3. только после OK копировать в /mnt/user-data/outputs/
```
**Никогда не отдавай файл без `node --check`.** История проекта знает случаи,
когда непроверенный патч уходил пользователю битым.

## 3. Архитектура движка

Один `<script>` в конце `<body>`. Ключевые глобалы:

| Имя | Что это |
|---|---|
| `VW=480, VH=270, TILE=32` | вьюпорт и тайл |
| `IMG` | словарь Image-объектов по ключам спрайтов |
| `G` | глобальное состояние игры (state, level, hp, pollen, inv, F-флаги, deaths, scroll...) |
| `P` | игрок {x,y,w,h,vx,vy,onG,wz(в воде),inv(неуязв.),pushing...} |
| `world` | текущий уровень: {def,W,H,gy,solids[],ents[],push[],checkpoint,seeds[],mireT} |
| `camX, camY` | камера (вертикальная поддерживается; для legacy-уровней H=270 → camY=0) |
| `keys` | зажатые клавиши; `eContextLock` — блок тяги после контекстного E |
| `LEVELS` | [null, buildL1..buildL12, L13-строка]; элемент может быть функцией ИЛИ DSL-строкой |
| `LVL_TEST` | def тест-уровня; `loadLevel(99)` грузит его |
| `DLG` | все диалоги; `DLGOVR` — оверрайды текстов из localStorage |
| `SKYPAL` | пресеты неба: act1, act2, act2b, act3, act3d, act4, dawn |
| `ED` | модуль редактора (IIFE в конце скрипта): {open, close, isOpen} |

**Состояния `G.state`:** title / controls / actsel / prologue / interlude / actcard /
play / epilogue / credits. Редактор — DOM-оверлей `#edWrap`, при открытии ставит
`G.state='title'`.

**Игровой цикл устойчив к ошибкам:**
```js
function loopBody(t){ ...вся логика и отрисовка... }
function loop(t){ try{ loopBody(t); } catch(err){ console.error('Ошибка кадра:',err); }
  requestAnimationFrame(loop); }
```
Любое исключение кадра логируется, но НЕ убивает игру. Не ломай эту обёртку.

**Вертикальная камера:** `world.H` (legacy=270), `targetY` по игроку,
`ctx.translate(-camX,-camY)`, параллакс-слои сдвигаются по Y с коэффициентами
(bgr ~0.88, дальняя полоса ~0.94), void-смерть при `P.y > world.H+50`,
дождь спавнится от `camY-6`, дыры тьмы (drawDark) учитывают camY.
`G.camFocus={x,y,t}` — временный фокус камеры (используется рычагами).

## 4. Игровые системы

### 4.1 Физика игрока
- Прыжок `vy=-375` → высота ~50px. **Следствие: подъём на 32px (1 тайл) возможен,
  на 64px (2 тайла) — НЕТ.** Вся геометрия уровней строится на ризах по 32px.
- Corner correction ≤10px, coyote time 0.12s, jump buffer.
- Горизонтальный зазор прыжка: безопасно ≤64px, предел ~80px.

### 4.2 Вода (`def.waters`)
Безопасна: выталкивание, плавание, прыжок у поверхности (depth<30 → coyote),
утонуть нельзя. Отрисовка тайлами water1-6.

### 4.3 Плавучесть толкаемых
В `updatePush`: ящик/бочка/горшок (не heavy) в воде получают буйянс
(−2500*dt при погружении >8px, демпфер `vy*=pow(.45,dt*3)`, кламп ±85),
`o.fallFrom=null` в воде — **хрупкие не бьются о воду**, всплеск при входе
(`o.wasW` отслеживает переход). Камни (heavy) тонут. На плавающий ящик можно
встать — это «плотик», легитимный дизайн-приём.

### 4.4 Выталкивание на кромку
`tryMovePush`: если X-движение блокировано солидом, чей верх не выше дна ящика
на ≤14px и сверху свободно — ящик поднимается на кромку (`o.py=s.y-o.h`) и
проходит. Так плавающий ящик выталкивается из воды на берег. Работает и на суше.

### 4.5 Трясина (`def.mires`) — ОПАСНАЯ жидкость
Касание: `hurt(1)` + выброс вверх (vy=-280) + вбок. Каждые ~1.9с из случайной
зоны вылетает горящее семя (спрайт burnseed, дуга, урон при касании, гаснет
в трясине/за миром). **КРИТИЧНО:** спавнер защищён `world.def.mires && world.def.mires.length`
— пустой массив без guard вызывал краш (исторический баг). Переправа — брёвна mplat.

### 4.6 Толкание и тяга
- Толкать: идти в объект. Скорость толкания тяжёлых (rocks) ниже.
- **Тянуть: зажать E**, стоя вплотную (Shift/X удалены).
- Конфликт E-действия и E-тяги решён через `eContextLock`: если при нажатии E
  рядом есть контекст (`findContext()` вернул действие) — выполняется действие,
  тяга блокируется до отпускания клавиши. Контекста нет → E работает как тяга
  (`GRAB = () => keys.KeyE && !eContextLock`).
- Толкать/тянуть можно вплавь (`P.onG || P.wz`).

### 4.7 Механики уровней
| Тип | Поведение | Ключевые поля |
|---|---|---|

| `vines` | лоза: ↑↓ лезть, прыжок со схода vy=-330, выход наверх | x,y1,h |
| `lblocks` + ent `lever` | рычаг (1 капля росы, необратимо, флаг `lv_<id>`) опускает блок на `drop` px за 0.6с; camFocus на блок; во время спуска блок выдавливает игрока к ближайшему боку (нельзя оказаться внутри) | id связывает |
| ent `tp` | телепорт-кольцо, активация E, пары по id/pair, cooldown 1.2с (спрайт tp_off), камера снап | id, pair |

### 4.8 Диалоги и тексты
- `DLG` — объект всех веток. Узел: `{sp:'Имя', face:'спрайт', t:'текст', ch:[[label,goto,act],...]}`.
- `startDialog(id)` применяет `applyOvr(id, DLG[id])` — оверрайды из `DLGOVR`
  (localStorage `garden_dlg`, формат `{dlgId:{nodeIdx:{t, ch:{j:label}}}}`).
  Оверрайдится только текст и подписи кнопок, НЕ логика переходов.
- `sign` (табличка) и `board` (доска объявлений) — тексто-носители с полем `txt`,
  читаются по E. board — крупная вывеска; рисуются ОТ ЦЕНТРА.
- **`textBox(opts)`** — универсальный вывод текста: перенос по ширине →
  авто-ужатие шрифта base→min → прокрутка (G.scroll, ▲▼, ↑↓/колесо) при
  переполнении. Опции: {text,x,y,w,h,color,base,min,lh,align,bold,shadow}.
  `lh` фиксирует межстрочный; `min=base` запрещает ужатие.
- Экраны пролога/интерлюдий/эпилога берут текст через
  `txOvr(key,page,default)` — те же оверрайды по псевдоключам
  `__prologue`, `__inter_to2/to3/to4/fin`, `__epilogue`.

### 4.9 Повествовательные экраны (story screens)
`drawStoryScreen(picKey, text, page, total)`:
- фон: `IMG.bgr1` на весь экран (вписан по ширине, низ к низу, верх дозалит
  градиентом неба в цвет кромки), затемнение к низу;
- по центру рамка картинки (пропорция ~1.6:1, размер от свободного места);
- нижнее текстовое окно В ТОЧНОСТИ как игровой диалог: фон rgba(24,16,10,.93),
  рамка #c29355 2px, текст СТРОГО 10px/lh12, align left, без ужатия
  (`base:10,min:10,lh:12`); счётчик и [E] в нижних углах окна.
- Окно bh=96 → текстовая зона 64px → максимум 5 строк по 12px. Тексты страниц
  не должны превышать 5 строк при 10px (≈ ширина 432px, ~72 символа/строка).

**Картинки:** ключ `'<screenKey>:<pageIndex>'` (напр. `__inter_to3:1`).
- `STORY_DEFAULT` — встроенные (плейсхолдер `__STORY_IMAGES__` при сборке).
- `STORYPIC` — пользовательские из localStorage `garden_story_pics` (приоритет НАД встроенными).
- `storySrc(key)` → STORYPIC[key] || STORY_DEFAULT[key]; `STORYIMG` — загруженные Image.
- Все 17 кадров встроены (360px JPEG q82, ~15КБ каждый). Маппинг листов
  генерации: 1→пролог, 2→to2, 3→to3, 4→to4, 5→fin(2 панели), 6→эпилог.
  Нарезка: ровные трети высоты 3504px → (20,1150),(1180,2320),(2350,3490);
  fin: (8,1730),(1775,3490). НЕ использовать авто-обрезку по яркости — тёмные
  панели ею режутся.

### 4.10 Прочее
- **Сейв:** localStorage `garden_save` (уровень-маркеры 4/7/10; уровни 13/99 не сейвятся).
- **Чекпоинты:** фонари (lit → world.checkpoint=[x,y], вертикаль поддержана).

## 5. Уровни

### 5.1 Загрузка — порядок приоритетов в `loadLevel(n)`:
```
1. n===99 && LVL_TEST            → тест из редактора
2. localStorage 'garden_lvl_<n>' → DSL-оверрайд (правки игрока через редактор!)
3. LEVELS[n]: строка → convertDSL(parseLVL(str)); функция → вызов
```
**Помни про п.2:** у пользователя могут жить правки уровней в браузере. Они
переживают пересборку файла. «Сбросить правки уровня» в редакторе удаляет ключ.

### 5.2 def-формат (то, что отдают билдеры и convertDSL)
```
{name,W,H,gy,sky:[4 цвета],hor,mus,dark,rain,bgr,
 terrain:[{x,y,w,h,f,top}](тайловые координаты),gaps:[[x,w]],
 waters/mires:[{x,y,w,h}](px), mplats,vines,lblocks,walls, spawn:[x,y], ents:[E(...)]}
```
- `E(t,x,y,opts)` — фабрика сущности. Наземные типы привязываются через `g`
  (опора Y) — список DSL_GROUND/anchored в loadLevel. Items (pollen/dew/berry)
  имеют абсолютный y. push — через `top` (Y опоры).
- **Список anchored-типов в loadLevel НУЖНО пополнять при добавлении новых
  наземных типов** — исторический баг: tp/spikes/trap/boulder падали на gy,
  пока их не внесли.

### 5.3 Уровень 13 «Корни-Глубины»
DSL-строка `L13` в шаблоне (3520×1088, dark, bgr=2). Адаптация карты Эрика
Робертса: спуск лозами → верхняя тропа (шаги по 32px!) → колодец с шипами →
лестница с валуном → коридор ловушек с приманками → трясина с 3 брёвнами →
финал (рычаг-секрет со статуей, телепорты A↔B экспресс и C↔D лифт). Доступ:
меню «Выбор акта» → «Тест: Корни-Глубины» (пресет инвентаря в loadGame ветке else).

## 6. DSL уровней (полная спецификация)

Строка = команда. Текст после `|` — до конца строки. Координаты px, кроме `t`/`gap` (тайлы).

```
#13 Имя уровня
@ W3520 H1088 sky=act4 mus=dark g=992 fl=dark,rain bgr=2
t dirt 0,31,65,3 ^        терраин: семейство x,y,w,h (тайлы); ^ = травяная кромка
gap 36,2                  пролом в базовой земле (тайлы)
wt 512,1004,192,60        вода (px)
mr 2080,1004,768,52       трясина
mp 2110,980,2206,980,36   бревно: x1,y1,x2,y2,скорость
vn 200,320,224            лоза: x, y верха, высота
lb 2920,884,36,54,k1,54   блок на цепи: x,y,w,h,id,спуск
wl 1240,flagName          стена-флаг
sp 40,320                 спавн (x,y)
e тип x,y [k=v ...] [|текст]
```
Сущности: `e sign 92,320 |Текст`, `e push 606,992 spr=crate frag=1 drop=pollen`,
`e tp 620,992 id=A pair=B`, `e npc 240,992 id=sproutling dlg=act3_sprout`,
`e boulder 1600,864 dir=-1`, `e spikes 1024,992 w=48`, `e board 300,992 |Объявление`.

Парсер в игре: `parseLVL(txt)` → промежуточный объект → `convertDSL(p)` → def.
- DSL_DECOR_SPR = ['statue','bench','wheat','drybush','berrybush'] → конвертируются
  в `decor` с spr (**board ИСКЛЮЧЁН** — он интерактивный тексто-носитель).
- items получают y-16 (визуальный лифт), наземные — g=y, push — top=y.

## 7. Встроенный редактор (модуль ED)

Открытие: главное меню → «Редактор уровней». DOM-оверлей `#edWrap`, строится
лениво в `buildDOM()`. Esc — закрыть. Игровая клавиатура «глушится» через
`ED.isOpen()` guard в начале keydown.

### 7.1 Модель M
```
{num,name,W,H,g,sky,mus,dark,rain, grid[rows][cols] (família|0),
 waters,mires,mplats,vines,lblocks,walls, ents:[{t,x,y,...props}], spawn}
```
- `defToModel(def,num)` ←→ `exportDSL()` — round-trip БЕЗ ПОТЕРЬ (проверен).
  Терраин экспортируется построчными полосами с признаком открытости (^).
- Загрузка уровня: селектор 1-13 → loadLv(n) (учитывает localStorage-оверрайд).

### 7.2 Палитра (верхняя панель)
Вкладки PCATS: Террейн / Зоны / Механики / Персонажи / Опасности / Предметы /
Толкаемые / Декор. Плитки `.ptile` с canvas-иконками из реальных спрайтов.
`palItems(cat)` — генератор; decor-пресеты фильтруются по наличию в IMG
(новые спрайты в паке подхватываются сами). NPC — пресеты с id
(sproutling, daisy_keeper, mushroom_sage, guardian_wasp, thorn_sovereign,
singing_willow, wilted_queen, shadow_gardener) + спец-типы acorn/entb/beast/chomper.
**Постановка без prompt'ов:** дефолты + авто-метки (`nextTpId` A,B,C...;
`nextLevId` s1,s2...), объект сразу выделяется с открытой панелью свойств.

### 7.3 Якоря отрисовки — КРИТИЧНО
Игра рисует decor (и statue/bench/wheat/drybush/berrybush через decor) и push
**ОТ ЛЕВОГО КРАЯ** (`e.x` = левая кромка); всё остальное (npc, sign, board,
items, механики) — **ОТ ЦЕНТРА**. Редактор зеркалит это через
`ELEFT=['decor','statue','bench','wheat','drybush','berrybush','push']` и
`eBox(e)`. Менять якорь в ИГРЕ нельзя — поплывут 12 готовых уровней.
Постановка/перетаскивание учитывают якорь (визуально под курсором, drag с
офсетом захвата), хитбоксы по eBox.

### 7.4 Триггеры и связи
- На холсте: tp → `◈A → B` + пунктир к паре + «нет пары!»; lever → `⚙id` +
  линии к блокам; boulder → стрелка направления; spikes/trap/pit → подписи и зоны.
- Выделение подсвечивает связанный объект (рычаг↔блок, телепорт↔пара) с ОБЕИХ сторон.
- Панель свойств (`showProps`): TRIG_HELP/KIND_HELP — пояснения; связи —
  выпадающими списками из СУЩЕСТВУЮЩИХ меток (selectField); живые проверки
  (⚠ нет пары / кнопка «связать взаимно» / ✓); FIELD_LABEL/KIND_LABELS —
  человеческие подписи полей; txt — textarea.
- NPC спрайт в редакторе = `IMG[e.id]` (как в игре). Заглушки без спрайта
  подписываются именем типа (анонимных розовых квадратов быть не должно).

### 7.5 Тексты и диалоги (правая панель)
Селектор: все ключи DLG + псевдоэкраны (__prologue, __inter_*, __epilogue).
`renderDlg(key)`: textarea на каждую реплику + инпуты на подписи выборов.
«Сохранить тексты» → DLGOVR → localStorage `garden_dlg`, игра подхватывает сразу.
**Автоподгрузка:** клик по сущности с dlg/dlgAfter — или спец-персонажу
(SPECIAL_DLG: entb/beast/chomper/acorn/gate/relic) — переключает панель на его ветку.
Для story-экранов под каждой страницей — блок картинки: превью +
Добавить/Заменить/Убрать (file input → dataURI → STORYPIC → localStorage).
Пользовательская картинка ПЕРЕКРЫВАЕТ встроенную; «Убрать» возвращает встроенную.

### 7.6 Сохранение и тест
- «▶ Протестировать уровень» → LVL_TEST=convertDSL(parseLVL(exportDSL())) →
  startPlay(99) с полным инвентарём; выход/Esc → обратно в редактор.
- «▶ Сохранить в игру» → localStorage `garden_lvl_<num>` + индикатор
  «играется из ПРАВОК»; «Сбросить правки» → откат к встроенной версии.
- Undo: Ctrl+Z, стек 30 снапшотов (pushU на каждый mousedown).

## 10. Конвенции правок кода

1. **Правь ТОЛЬКО `garden_template.html`**, потом пересобирай (см. §2).
2. Патчи — python `str.replace(old,new,1)` по ТОЧНЫМ якорям. Перед патчем —
   `grep -n` якоря; собирай misses и **assert not miss** ДО записи файла
   (паттерн «собрал misses → один assert» предотвращает частично применённые патчи).
3. После сборки: `node --check`. При добавлении уровней/геометрии — прогнать
   валидатор (val13.js знает лозы/телепорты/брёвна/lblock-ступени; правила:
   риз ≤60px ⇒ фактически 32px на тайлах, hgap ≤80px).
4. Шаблон содержит template literal с backtick (L13) — следи за вложенными
   бэктиками в новых вставках.
5. Хвост файла: `</script>\n</body>\n</html>` (с переносами) — учитывай в якорях.
6. Новые наземные типы сущностей → добавить в: anchored-список loadLevel,
   DSL_GROUND, ESPR редактора, палитру palItems, (если левоякорный — ELEFT).
7. Пустые массивы зон НЕ означают отсутствие свойства — guard'ь `.length`
   перед случайным индексом (класс бага «спавнер семян»).
8. Скриншоты от пользователя могут быть со СТАРОЙ сборки (кэш) — прежде чем
   «чинить», сверь поведение с текущим кодом.
