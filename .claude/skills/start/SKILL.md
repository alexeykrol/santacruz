# Skill: Start Session — Санта-Круз

Литературный проект. Старт сессии состоит из двух блоков: общий и писательский. Писательский блок обязателен — без него агент уезжает в протокольный текст без ритма и канона (см. историю эп.003 v1/v2).

---

## Блок A — всегда (общий)

### A.0. Crash recovery
```bash
cat .claude/.last_session 2>/dev/null
```
- Если `"status": "active"` → предыдущая сессия упала: проверить `git status`, прочитать `SNAPSHOT.md`, спросить «продолжить или сначала закоммитить».
- Если `"status": "clean"` → продолжить.

### A.0b. Resume из прошлой сессии
- `Read .claude/LAST_SESSION.md` — автоматический хвост прошлой сессии (обновляется хуком `Stop` после каждого ответа ассистента).
- В докладе пользователю (см. финал) **обязательно процитировать**:
  - последние 2–3 пользовательских реплики из секции «Хвост последних пользовательских реплик»;
  - 1–2 предложения из «Последний ответ ассистента» — чтобы пользователь понял, где остановились.
- Если файла нет (первый запуск с этим хуком) — просто отметить «прошлая сессия не зафиксирована» и идти дальше.

### A.1. Mark session active
```bash
echo '{"status": "active", "timestamp": "'$(date -Iseconds)'"}' > .claude/.last_session
```

### A.2. Прочитать состояние
- `Read .claude/SNAPSHOT.md` — текущее состояние, на каком эпизоде стоим
- `Read .claude/FILE_INDEX.md` — каталог 150+ файлов, секции «pre-task reading lists» и «quick answers»

### A.3. Git
```bash
git status --short
git log --oneline -5
```

### A.4. Лог сессии
```bash
mkdir -p .claude/logs/sessions
```
Создать `.claude/logs/sessions/YYYY-MM-DD_HH-MM.md` с timestamp, SNAPSHOT-статусом, git-статусом.

## Блок B — обязателен перед любой работой с текстом эпизодов

Если в этой сессии ожидается работа с черновиком, канвой, диагностикой, правкой, дописыванием — этот блок выполнить **до первой строчки текста**. Если сессия чисто инфраструктурная (правки скиллов, коммиты, PR) — можно отложить.

При сомнении — выполнить. Цена пропуска (протокольный текст без ритма) выше цены чтения (минута–две).

### B.1. Метод и процесс
- `Read .claude/WRITING_METHOD.md` — приёмы, ритм, юмор, посадки, эхо
- `Read .claude/EPISODE_PROCESS.md` — путь от канвы к финальному тексту, карта повторяющихся ошибок

### B.2. Канон
- `Read development.md` — канонические факты сюжета (что нельзя менять)
- `Read research/episode-mapping/BIBLE.md` — Conrad mapping, архитектура цепочки эпизодов, Want/Need/Deserve

### B.3. Реестр посеянных артефактов
- `Read 3_stories/santa_cruz_incident/seeded_artifacts.md` — что нельзя противоречить, к чему нужно возвращаться

### B.4. Контекст текущего эпизода (по SNAPSHOT)

В проекте две зоны для эпизодов:
- `drafts/episodeNNN/` — **публичная**: только утверждённые финальные версии
- `_personal/drafts/episodeNNN/` — **личная**: все промежуточные черновики, канвы, версии в работе

По номеру текущего эпизода (из SNAPSHOT.md) — прочитать в порядке:
1. Если в `drafts/episodeNNN/` есть утверждённая версия — прочитать её (это текущий канонический текст эпизода)
2. **Обязательно** заглянуть в `_personal/drafts/episodeNNN/` — там самые свежие черновики и канва, над которыми идёт активная работа. Прочитать последнюю версию по номеру и канву если есть (`canvas-*.md`)
3. Эталон ритма — всегда `drafts/episode001/episode001-v8.1.md` (это эталонный текст проекта, лежит в публичной зоне)

Если работа над эп.003 — последняя версия и канва **точно** в `_personal/drafts/episode003/`. В публичной `drafts/episode003/` пусто до момента принятия.

## Правила

- **Не показывать содержимое файлов пользователю** — только статус «загружено».
- **Не запускать тесты** — это `/finish`.
- **Не коммитить автоматически** — если есть незакоммиченное, сообщить.
- **Не дольше 60 секунд** в общем случае. Блок B сам по себе — около 30 секунд чтения.
- **При несовместимости с CLAUDE.md** — приоритет у этого SKILL.md. CLAUDE.md описывает общий шаблон фреймворка, SKILL.md — специализацию для литературного проекта.
